The problem

Why it exists

A police IT department has several jobs that usually live in separate places: checking that personnel meet fitness standards, knowing whether a server room is being broken into or overheating, and keeping track of every computer, printer and router. PNP ITMS brings them into one login-protected platform.

How it works

One BMI check, five steps

The fitness kiosk is the most hands-on of the five systems. Here is what happens when an officer is measured.

  1. Tap your card

    The RFID reader identifies the officer.

    RC522 · height board

  2. Admin starts the session

    An admin starts a measurement session on the website. The kiosk is waiting for that signal.

    Web app · REST API

  3. Height

    Stand under the sensor. A small screen says what to do.

    HC-SR04 + 16x2 LCD · height board

  4. Weight

    Step on the scale. The reading is sent once it settles.

    HX711 load cell · scale board

  5. Result

    The backend works out BMI and ideal body weight and classifies it, then it appears on the dashboard.

    NestJS · MySQL · React

BMI is classified against both the WHO bands and an age-adjusted PNP “Acceptable BMI” table. [Confirm the order of the steps.]

What’s inside

Five systems, one login

Each system has its own page, its own data, and its own role-scoped access.

BMI System

Measures height and weight at a kiosk and classifies the result, with dashboards, trends and PDF reports.

ESP32 · RFID · ultrasonic · load cell

Intrusion Detection

Shows live status of a beam-break sensor and keeps a log of genuine triggered and clear events.

ESP32 · laser/LDR beam · buzzer · SMS

Environment Monitoring

Tracks temperature and smoke, and classifies each reading as normal, smoke detected, or high temperature.

ESP32 · SHT31 · MQ-2

Hardware Inventory

Tracks IT assets by division and person, either entered by admins or reported automatically by a collector agent.

REST API · shared-secret agent

PC Information

Imports a forensics-tool export and shows security findings, connections and component health for each machine.

CSV import · security assessment

    Challenges & solutions

    Problems solved

    An alarm that never waits on the network

    THE PROBLEM
    If Wi-Fi or the server is down, a break-in or a fire alarm should still sound.
    WHAT I DID
    The safety board runs its buzzer and SMS alert on its own, with or without Wi-Fi. The website only receives the events when it can.
    THE RESULT
    The alarm never depends on the network. [Add a test you ran, e.g. unplugged the router and the alarm still sounded.]

    Building before the sensors arrived

    THE PROBLEM
    The laser, smoke and temperature parts were not wired up yet, but the website and API needed testing end to end.
    WHAT I DID
    Wrote test-mode firmware: the BOOT button simulates a broken beam, and fake readings drift like real ones. Each sketch says exactly where to swap in the real sensor.
    THE RESULT
    The whole path from board to dashboard was tested first, then a real-sensor version of the safety board was written to take over from the test sketches.

    Fair BMI for different ages

    THE PROBLEM
    A single BMI cut-off does not match the police standard, which allows a higher BMI as officers get older.
    WHAT I DID
    Classified every reading against both the WHO bands and the age-adjusted PNP table, whose upper limit widens from 24.9 at 29 or younger to 27.0 at 51 and over.
